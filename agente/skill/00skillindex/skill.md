# Skills para Proyecto de App de Centros Deportivos (Fútbol y Pádel)

## 📋 Resumen General

Este conjunto de 6 skills especializados cubre todos los aspectos del desarrollo de una aplicación moderna para gestionar centros deportivos con servicios de fútbol y pádel.

## 🎨 1. [**frontend-sports-center.SKILL.md**](../frontend-sports-center.SKILL.md)

**Rol**: Diseñador Frontend / UX Engineer

### ¿Cuándo usarlo?
- Crear interfaces de usuario modernas y responsivas.
- Desarrollar dashboards de disponibilidad en tiempo real.
- Implementar flujos de reserva rápidos y seguros.
- Integrar visualizaciones de datos para reportes y analíticas.
- Optimizar la experiencia de usuario en dispositivos móviles y web.

### Áreas clave:
- Desarrollo con React/Next.js y Tailwind CSS.
- Gestión de estado eficiente (Zustand/Redux).
- Animaciones y micro-interacciones premium (Framer Motion).
- Accesibilidad y performance (First Contentful Paint optimizado).
- Implementación de sistemas de diseño consistentes.

### Ejemplo de uso:
*"Crea un dashboard de disponibilidad de canchas con grid 3x3 que se actualice en tiempo real y sea 100% responsivo"*

---

## 🔧 2. [**backend-sports-center.SKILL.md**](../backend-sports-center.SKILL.md)

**Rol**: Backend Developer / API Engineer

### ¿Cuándo usarlo?
- Diseñar arquitectura de API robusta para gestión de centros.
- Implementar lógica de negocio compleja (reservas recurrentes, cancelaciones).
- Gestionar pagos, suscripciones y facturación.
- Crear sistemas de disponibilidad en tiempo real con detección de conflictos.
- Desarrollar módulos de reportes y analíticas de ingresos.

### Áreas clave:
- APIs RESTful/GraphQL seguras y escalables.
- Gestión de roles (admin, manager, player) y autenticación JWT.
- Integración con pasarelas de pago (Stripe/PayPal) vía webhooks.
- Sincronización en tiempo real (WebSockets/Polling).
- Optimización de queries de base de datos para alta concurrencia.

### Ejemplo de uso:
*"Implementa el flujo de reserva recurrente que valide conflictos de horario y procese el pago mensual automáticamente"*

---

## 🗄️ 3. [**database-sports-center.SKILL.md**](../database-sports-center.SKILL.md)

**Rol**: Database Architect / DBA

### ¿Cuándo usarlo?
- Diseñar esquemas optimizados para gestión de canchas y reservas.
- Crear modelos de datos escalables para usuarios, equipos y pagos.
- Implementar estrategias de indexación y particionamiento de tablas.
- Garantizar la integridad de los datos y reglas de negocio en la DB.
- Optimizar consultas críticas de disponibilidad y reportes financieros.

### Áreas clave:
- Modelado entidad-relación (ERD) para centros deportivos.
- Optimización de performance (índices, caché con Redis, vistas materializadas).
- Integridad referencial, constraints y validaciones de datos.
- Estrategias de backup, recuperación y archivado de datos históricos.
- Seguridad de datos sensibles y cumplimiento de normativas.

### Ejemplo de uso:
*"Diseña el esquema de base de datos para manejar 100K+ reservas mensuales con consultas de disponibilidad en menos de 100ms"*

---

## 📱 4. [**mobile-sports-center.SKILL.md**](../mobile-sports-center.SKILL.md)

**Rol**: Mobile Developer (React Native / Flutter)

### ¿Cuándo usarlo?
- Desarrollar apps nativas o multiplataforma (iOS/Android).
- Implementar capacidades offline y sincronización de datos.
- Configurar notificaciones push en tiempo real (recordatorios, avisos).
- Utilizar geolocalización para mapas y check-ins en el complejo.

### Áreas clave:
- Desarrollo con React Native o Flutter para despliegue rápido.
- UI/UX optimizada para uso en campo (alto contraste, targets grandes).
- Gestión de estado local y persistencia (SQLite/Realm).
- Integración con APIs optimizadas para dispositivos móviles.
- Seguridad biométrica y almacenamiento seguro de credenciales.

### Ejemplo de uso:
*"Crea una pantalla de reserva en React Native que permita seleccionar horario en 2 taps y funcione sin conexión"*

## 🔌 5. [**integrations-sports-center.SKILL.md**](../integrations-sports-center.SKILL.md)

**Rol**: Integration Specialist / DevOps Engineer

### ¿Cuándo usarlo?
- Integrar pasarelas de pago (Stripe, PayPal, Square).
- Configurar servicios de comunicación (Twilio, SendGrid, Firebase).
- Sincronizar agendas con Google Calendar u Outlook.
- Conectar plataformas de analytics (Google Analytics, Mixpanel).
- Gestionar webhooks, autenticación OAuth2 y manejo de errores de terceros.

### Áreas clave:
- Arquitectura de integraciones robusta (Webhooks, Polling, Event Streaming).
- Manejo de seguridad en pagos (PCI Compliance, Tokenización).
- Sincronización de zonas horarias y calendarios externos.
- Implementación de lógica de reintentos (Exponential Backoff, Circuit Breaker).
- Monitoreo de cuotas y performance de APIs externas.

### Ejemplo de uso:
*"Configura un webhook de Stripe que valide la firma, confirme el pago y sincronice automáticamente la reserva con el Google Calendar del usuario"*

## ✅ 6. [**testing-deployment-sports-center.SKILL.md**](../testing-deployment-sports-center.SKILL.md)

**Rol**: QA Engineer / DevOps / Release Manager

### ¿Cuándo usarlo?

- Procesos de QA y checklists pre-release para asegurar estabilidad.

### Ejemplo de uso:
*"Configura el pipeline de CI/CD que ejecute tests unitarios, de integración y E2E antes de desplegar automáticamente a staging"*

## 📚 Flujo Típico de Desarrollo

### Sprint 1: Concepción y Estructura
1. **Product**: Define visión y requerimientos.
2. **UI/UX**: Diseña prototipos y sistema de base.
3. **Database**: Define esquema con `database-sports-center`.

### Sprint 2-3: Desarrollo Core
1. **Backend**: Crea APIs críticas.
2. **Frontend**: Implementa UI basada en diseños.
3. **Integrations**: Conecta pagos y calendarios.

### Sprint 4: Growth y Calidad
1. **Marketing**: Configura campañas y lealtad.
2. **Testing**: Pruebas E2E y performance.
3. **Mobile**: Lanza apps para iOS/Android.

1. **Testing**: CI/CD pipeline setup
2. **Deployment**: Stagings → Production
3. **Monitoring**: Alertas y observabilidad

## 💡 Ejemplos de Prompts por Skill

### Frontend
```
"Crea un componente React de disponibilidad de canchas que muestre:
- Fecha y hora selectables
- Grid 3x3 de canchas (fútbol/pádel)
- Estado en tiempo real (verde=libre, rojo=ocupado, gris=mantenimiento)
- Precio dinámico según horario
- Botón de reserva directo"
```

### Backend
```
"Implementa el endpoint POST /api/bookings que:
- Valide conflictos con reservas existentes
- Calcule el precio (base + descuento miembro)
- Procese el pago con Stripe
- Cree la reserva en DB
- Envíe email de confirmación"
```

### Database
```
"Diseña el esquema para almacenar:
- 50 canchas de fútbol/pádel
- 100K+ bookings mensuales
- Usuarios con membresías
- Transacciones de pago
- Analytics de ocupación
Optimiza para queries de disponibilidad <1s"
```

### Mobile
```
"Crea la pantalla de booking en React Native que:
- Muestre canchas disponibles en mapa
- Permita seleccionar fecha/hora
- Procese pago con Stripe
- Muestre confirmación con código de reserva
- Envíe a Google Calendar"
```

### Integrations
```
"Configura el flujo de pago:
- Crear token de tarjeta con Stripe
- Procesar pago en backend
- Webhooks para confirmar/fallar pago
- Sincronizar con contabilidad
- Enviar recibo por email"
```

### Testing
```
"Escribe tests completos para:
- Validación de conflictos de bookings
- Flujo de pago exitoso/fallido
- Cálculo dinámico de precios
- E2E: booking → pago → confirmación
- Load test: 1000 bookings concurrentes"
```

## ❓ Preguntas Frecuentes

**¿Por dónde empiezo?**
1. Empieza con Database (entiende tu modelo de datos)
2. Continúa con Backend (implementa la lógica)
3. Luego Frontend (conecta a las APIs)
4. Testing y Deployment (asegura calidad)

**¿Puedo hacer cambios en el skill?**
Sí, puedes personalizar los prompts según tus necesidades específicas. Los skills son guías, no reglas rígidas.

**¿Cómo uso estos skills en mi desarrollo?**
Copia el contenido del skill relevante cuando hagas un prompt a Claude. Ejemplo:
```
[Copiar contenido de frontend-sports-center.SKILL.md]

"Ahora crea el componente de disponibilidad de canchas..."
```
